# Contributing

Thanks for your interest in contributing. This project is a portfolio piece, but
issues and pull requests are welcome.

## Development Setup

```bash
# Create and activate a virtual environment
python -m venv .venv
.venv/Scripts/activate      # Windows
# source .venv/bin/activate # macOS/Linux

# Install runtime + dev dependencies (ruff, mypy, pytest)
pip install -r requirements-dev.txt

# Copy and fill in environment variables
cp .env.example .env
```

## Lint, Type-Check, and Test

```bash
ruff check .          # lint
mypy app              # static type checking
pytest -v             # full test suite
```

All three must pass before submitting a PR. Tests that need a real
`OPENAI_API_KEY` / `LANGFUSE_*` / `LANGCHAIN_API_KEY` are automatically skipped
when those secrets are not configured, so the suite runs green with zero
secrets.

## Proposing a Prompt Change

Prompts are versioned artifacts under `prompts/`; never edit an existing
`vN.yaml` (versions are immutable). Instead:

1. Run the service locally (`PROMPT_ADMIN_OPEN=true` or an `AGENTIC_API_KEY`)
   and create a candidate: `POST /api/v1/prompts/planner/candidates`.
2. Review the change with `GET /api/v1/prompts/planner/diff?from=v1&to=v2`.
3. Run the A/B gate: `POST /api/v1/prompts/planner/ab-test`. A regression
   blocks promotion; the safety metric (`injection_block_rate`) can never
   be overridden.
4. Promote (`POST …/promote`) and confirm `GET /api/v1/prompts/audit`
   reports `valid: true`.
5. Open a PR containing the new `prompts/planner/vN.yaml` **and** the
   updated `prompts/registry.json` (generated by the API — never hand-edit
   hashes or audit entries). Run `python -m app.services.prompt_eval --check`
   before pushing.

If you add evaluation cases, edit `evaluation/planner_dataset.yaml`: assert
tool *selection* (never web-search output) and use `allowed_tools` lists for
ambiguous inputs.

## Conventions

- Type hints on all public functions.
- Follow the existing code style; `ruff` enforces it in CI.
- Commit messages use conventional prefixes (`feat:`, `fix:`, `refactor:`,
  `chore:`, `docs:`, `test:`).
